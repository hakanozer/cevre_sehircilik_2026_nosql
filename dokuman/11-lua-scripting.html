2. Eğitmen notu

Sınıfa açılış ve aktarım dili

“Lua script birden fazla Redis komutunu sunucu tarafında tek atomik işlem gibi yürütmemizi sağlar. Ancak atomiklik ücretsiz değildir: script çalışırken diğer komutlar bekler; küçük ve bounded script yazacağız.”

Sorulabilecek sorular
  • Script atomikse neden kısa tutulmalı?
  • EVALSHA NOSCRIPT dönerse client ne yapmalı?
  • Dağıtık lock'ı sadece SET NX ile bırakmak neden tehlikeli?
Sınıf içi tuzaklar

Lua atomicity isolation'dır, rollback değil; script error sonrası önceki yazılar kalabilir. `KEYS` array script argument'tır, tüm keyspace scan değildir. Script key'leri Cluster'da aynı hash slot'a düşmeli. Lock release owner token compare-and-delete yapmadan DEL etmeyin.

3. Kavramsal anlatım: neden → nedir → nasıl

Neden?

Rate limit kontrolünde GET count, koşul, INCR ve TTL ayrı round-trip olsa arada race olabilir. Lua ile tek server-side script execution içinde check/update yapılabilir.

Nedir?

`EVAL script numkeys key... arg...` script'i çalıştırır; `EVALSHA` SHA1 cache referansı kullanır. Script cache restart/flush sonrası kaybolabilir; NOSCRIPT recovery gerekir. Redis 7 Functions API'si de vardır fakat sürüm/operational model ayrı.

Nasıl?

Python redis-py `register_script` kullanır; script key/args ayrılır. Lab script fixed-window counter key'i increment edip ilk istek TTL koyar. Lock demo token compare+delete Lua ile güvenli release yapar. Rate limiter demo distributed sliding window değildir.

UZMAN NOTU · Üretim, performans ve güvenlik

Lua script süre/boyut limitlerini workload'a göre ölçün; uzun loop/blocking script tüm instance latency'sini etkiler. Rate limit key TTL ve atomicity; clock source/server time, policy, burst semantics; cluster hash tags gerekir. Lock TTL expiry, fencing token, lease renewal ve downstream fencing olmadan genel distributed lock doğruluk garantisi sayılmaz. Mümkünse Redlock/consensus tasarım iddialarını iş gereksinimi ve failure modeline göre inceleyin.

4. Adım adım uygulama (Lab)

Her checkbox sayfa içi ilerleme içindir; durum kaydedilmez. Komutları verilen sırayla uygulayın. Kod bloklarının sağ üstündeki Kopyala düğmesi içeriği panoya alır.

from __future__ import annotations

import os
import secrets
import time

import redis


RATE_LIMIT = """
local current = redis.call('INCR', KEYS[1])
if current == 1 then
  redis.call('EXPIRE', KEYS[1], ARGV[1])
end
local ttl = redis.call('TTL', KEYS[1])
return {current, ttl}
"""

RELEASE_LOCK = """
if redis.call('GET', KEYS[1]) == ARGV[1] then
  return redis.call('DEL', KEYS[1])
end
return 0
"""


def main() -> None:
    client = redis.Redis.from_url(
        os.getenv("REDIS_URL", "redis://localhost:6379/0"),
        decode_responses=True,
        socket_connect_timeout=2,
        socket_timeout=2,
    )
    try:
        rate_limit = client.register_script(RATE_LIMIT)
        result = rate_limit(
            keys=["rate:demo:user-7"],
            args=[60],
        )
        print("Rate window count/ttl:", result)
        token = secrets.token_urlsafe(24)
        acquired = client.set("lock:demo:job-1", token, nx=True, ex=10)
        print("Lock acquired:", bool(acquired))
        if acquired:
            time.sleep(0.1)  # Simulate a short, bounded critical section.
            release = client.register_script(RELEASE_LOCK)
            print("Lock released:", release(keys=["lock:demo:job-1"], args=[token]))
    finally:
        client.close()


if __name__ == "__main__":
    main()

RATE_LIMIT increments counter and sets expiry only at first hit; returns count/TTL. Lock token is random; SET NX EX acquires only if absent; Lua compare/delete avoids deleting another owner's lock. It is pedagogical, not complete fencing/lease system.

python lua_demo.py

Beklenen `Rate window count/ttl: [1, 60]` (TTL timing may be 59) and `Lock acquired: True`, `Lock released: 1`. Re-run counter count increments.

docker exec redis-lab redis-cli SCRIPT FLUSH

Yalnızca disposable lab'ta çalıştırın; script cache'i temizler. Ardından `python lua_demo.py` tekrar çalıştırıldığında redis-py `register_script` script'i tekrar yükleyip çalıştırmalıdır. Production/shared instance'ta `SCRIPT FLUSH` kullanmayın.

Bu demo fixed-window counter'dır; pencere sınırında burst iki katına yaklaşabilir. `RATE_LIMIT` key tenant/user identity'sini içerir. Cluster'da `rate:{user-7}:window` gibi braces ile aynı-slot key planlayın. Script'leri küçük tutun, load test edin, source file olarak version-control edin.

7. Mini alıştırmalar

Kolay

EVALSHA cache miss tipik olarak hangi hatayı verir?

Orta

Lock'u neden random token ile compare-and-delete yaparız?

Zor

Lua script atomik ama ortasında runtime error oluşursa tüm yazılar rollback olur mu?

Cevap anahtarını aç/kapat
  1. NOSCRIPT; script body ile EVAL fallback/load gerekir.
  2. Süresi dolan eski owner, lock'u yeni owner aldıktan sonra yanlışlıkla silemesin diye.
  3. Hayır. Atomic execution diğer komutların araya girmemesini sağlar; SQL rollback semantiği değildir.
