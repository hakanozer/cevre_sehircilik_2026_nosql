Data Structures I: String, List, Set, Hash

Sayfa 04 / 13Tahmini süre: 90 dkSeviye: Başlangıç → OrtaEğitim süresi: [X gün / Y saat]

Bu sayfa bağımsız HTML'dir; internet bağlantısı gerektirmez. Eğitim lab dosyaları redis-egitimi/docker/, redis-egitimi/python/ ve redis-egitimi/labs/ altında tutulur.

1. Öğrenme hedefleri

  • String ve TTL ile cache/counter örüntüsü kurmak
  • List ile uçlardan ekleme/çıkarma yapmak
  • Set üyeliği ve kesişim işlemlerini kullanmak
  • Hash'i nesne alanlarını saklamak için değerlendirmek

Bu sayfaya başlamadan önce hazır olması gerekenler

Compose Redis konteyneri çalışıyor; CLI açılabiliyor. Önceki sayfalardaki key prefix kuralını kullanın.

2. Eğitmen notu

Sınıfa açılış ve aktarım dili

“Veri yapısı seçimini sadece komut ezberlemek olarak görmeyin. E-ticaret sepeti, etiket üyeliği ve ürün özellikleri farklı erişim örüntüleridir; doğru tipi seçmek kodu ve atomik işlemleri sadeleştirir.”

Sorulabilecek sorular
  • Sepeti List mi Hash mi yaparsınız; hangi erişim gerekiyor?
  • Set ile List arasındaki üyelik farkı nedir?
  • INCR neden GET edip Python'da artırmaktan daha güvenlidir?
Sınıf içi tuzaklar

Redis Hash bir SQL tablosu değildir; bütün field'ları sorgulamak için sınırsız tarama yapmayın. List'i otomatik olarak dayanıklı message queue saymayın. TTL key seviyesindedir; tek Hash field'ına TTL gerektiğinde sürüm özelliklerini doğrulayın veya farklı key tasarlayın.

3. Kavramsal anlatım: neden → nedir → nasıl

Neden?

Veri yapısı, ihtiyacın sunucu tarafında atomik ve verimli ifade edilmesini sağlar. Ürün stok sayacı için `INCRBY`, kullanıcı etiket kümesi için Set, ürün alanları için Hash; bunların her biri uygulama tarafında veri çekip tekrar yazma ihtiyacını azaltır.

Nedir?

`String` byte string/sayı/counter; `List` sıralı tekrar edebilen öğeler; `Set` benzersiz üyeler; `Hash` field-value alanları. Tüm veriler key altında tutulur. Komut karmaşıklıkları veri büyüklüğüne göre değişir; büyük liste/Hash işlemlerini ölçün.

Nasıl?

CLI ile örnekleri çalıştırın; key'ler `lab:` namespace'i taşır. Liste push/pop uçlarını, Set SADD/SISMEMBER/SINTER'ı, Hash HSET/HGETALL'ı gösterir. Üretimde sınırsız büyüyen key'e TTL/retention veya kontrollü trimming planı gerekir.

UZMAN NOTU · Üretim, performans ve güvenlik

INCR/INCRBY tam sayı semantiğine göre atomik; uygulama GET+SET ise kayıp güncelleme riski taşır. `HGETALL` ve büyük `SMEMBERS` tam yapıyı döndürür; aşırı büyük yapılarda ağ/latency yükü yaratır. Sepet tutarlılığı, stok doğruluğu ve idempotency ayrıca tasarlanmalı; cache value tipi iş gereksiniminin tek kaynağı değildir.

4. Adım adım uygulama (Lab)

Her checkbox sayfa içi ilerleme içindir; durum kaydedilmez. Komutları verilen sırayla uygulayın. Kod bloklarının sağ üstündeki Kopyala düğmesi içeriği panoya alır.

docker exec -it redis-lab redis-cli

Prompt görülmeli.

SET lab:stock:SKU-42 8
INCRBY lab:stock:SKU-42 2
GET lab:stock:SKU-42

Çıktı: OK, integer 10, "10".

RPUSH lab:jobs job-1 job-2 job-3
LLEN lab:jobs
LPOP lab:jobs
LRANGE lab:jobs 0 -1

List length 3; pop `job-1`; kalan `job-2`, `job-3`. List alone ack/retry/durability semantics வழங்காது; reliable work stream için Streams değerlendirin.

SADD lab:user:7:tags redis python docker
SADD lab:user:8:tags python sql
SISMEMBER lab:user:7:tags redis
SINTER lab:user:7:tags lab:user:8:tags

İlk sonuç integer 1; kesişim `python` (Set sıralı değildir).

HSET lab:product:42 name "Pour-over" price_cents 2499 active 1
HGET lab:product:42 name
HGETALL lab:product:42
HINCRBY lab:product:42 price_cents 100

HSET new fields count 3; HGET `Pour-over`; HGETALL field/value çiftleri; HINCRBY 2599.

DEL lab:stock:SKU-42 lab:jobs lab:user:7:tags lab:user:8:tags lab:product:42
QUIT

Silinen key sayısı 5.

5. Beklenen çıktılar

String value 10; List length 3 then two pending items; Set membership 1 and intersection python; Hash price_cents 2599.

Zor
