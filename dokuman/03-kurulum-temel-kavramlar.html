Redis Installation and Fundamental Concepts

Sayfa 03 / 13Tahmini süre: 75 dkSeviye: Başlangıç + OrtaEğitim süresi: [X gün / Y saat]

Bu sayfa bağımsız HTML'dir; internet bağlantısı gerektirmez. Eğitim lab dosyaları redis-egitimi/docker/, redis-egitimi/python/ ve redis-egitimi/labs/ altında tutulur.

1. Öğrenme hedefleri

  • Docker run ve Compose ile Redis başlatmak
  • CLI ile key, TTL ve seçili veritabanı kullanmak
  • redis.conf/command parametrelerinin rolünü tanımak
  • Port, volume ve container yaşam döngüsünü açıklamak

Bu sayfaya başlamadan önce hazır olması gerekenler

Docker Desktop Running; 01. sayfadaki `redis-egitimi/docker/compose.yaml` hazır ve sabit Redis imajı etiketi seçilmiş olmalı.

2. Eğitmen notu

Sınıfa açılış ve aktarım dili

“Şimdi aynı sunucuyu iki yolla başlatacağız: tek seferlik docker run ve tekrar üretilebilir Compose. Bir lab komutunun çalışması kadar, verinin konteyner silinince ne olacağını anlamak da önemli.”

Sorulabilecek sorular
  • `docker rm` sonrası volume'daki veri silinir mi?
  • TTL anahtarın ne zaman silineceğini garanti eder mi?
  • Redis database index'i tenant izolasyonu için yeterli midir?
Sınıf içi tuzaklar

İç konteyner portu ile host portunu karıştırmayın. `docker run --rm` kullanıldığında container kaldırılınca writable layer silinir. Redis logical DB'leri güvenlik sınırı değildir ve Cluster'da çoklu DB desteği yoktur.

3. Kavramsal anlatım: neden → nedir → nasıl

Neden?

Tek komutlu deneme hızlıdır; tekrarlanabilir sınıf/ekip ortamı Compose dosyasıyla daha güvenilir olur. Host port eşlemesi uygulamaların bağlanmasını, volume ise konteyner değişse de veri dizininin saklanmasını sağlar.

Nedir?

Key'ler byte dizisi olarak değerlendirilir; Redis tipli value saklar. TTL saniye cinsinden `EXPIRE` veya yazma sırasında `EX` ile belirlenir. `SELECT` logical database seçer. `redis.conf` parametreleri dosyadan, command line'dan veya config set ile (desteklenen ayarlarda) uygulanabilir; Compose command ve bind-mounted config de kullanılabilir.

Nasıl?

Port `127.0.0.1:6379:6379` ifadesinde sol taraf host portu, sağ taraf container portudur. `docker run -d` tek container başlatır. Compose servis/volume ayarını deklaratif hale getirir. Key örüntüsü `app:entity:id:field` kullanıp kişisel/secret veriyi key'e yazmayın.

UZMAN NOTU · Üretim, performans ve güvenlik

Default DB index'i protokol/isim alanı kolaylığıdır, tenant authorization boundary değildir. Redis Cluster DB 0 dışında logical DB kullanımını desteklemez. TTL silinmesi yaklaşık zamanlama/erişim davranışına sahiptir; kritik deadline enforcement uygulama katmanında olmalı. Production config'i version-control ve secrets management ile yönetilmeli; `CONFIG SET` restart sonrası kalıcı olmayabilir.

4. Adım adım uygulama (Lab)

Her checkbox sayfa içi ilerleme içindir; durum kaydedilmez. Komutları verilen sırayla uygulayın. Kod bloklarının sağ üstündeki Kopyala düğmesi içeriği panoya alır.

A. Tek denemelik docker run

Windows · PowerShell: eğitim için doğrulanmış sabit imaj etiketini kullanın; `<major.minor.patch>` placeholder'ını değiştirin.

docker run -d --name redis-quick -p 127.0.0.1:6380:6379 redis:<major.minor.patch>

macOS/Linux · Terminal:

docker run -d --name redis-quick -p 127.0.0.1:6380:6379 redis:<major.minor.patch>

-d arka planda çalıştırır; --name sabit container adı verir; -p host 6380'i container 6379'a bağlar; redis:<sürüm> imaj etiketidir. Beklenen çıktı container ID. Bu örnek volume ve kalıcı ayar içermez; üretim kurulumu değildir.

docker ps --filter name=redis-quick

`redis-quick` ve `Up` beklenir.

docker exec -it redis-quick redis-cli -p 6379 PING

`PONG` beklenir.

docker rm -f redis-quick

`-f` çalışan container'ı durdurup kaldırır; bu geçici örnekte korunacak volume yoktur.

B. Ortak Compose servisini başlatma

cd $HOME\redis-egitimi\docker

macOS · Terminal:

cd ~/redis-egitimi/docker
docker compose up -d

`up` YAML'den container'ları oluşturur; `-d` detached mod. `compose.yaml` içindeki image etiketi gerçek sabit sürüm olmalı.

docker compose ps
docker compose logs --tail 30 redis

`ps` Up durumunu; `logs` son 30 satırı gösterir. Normal başlatmada fatal error olmamalı.

C. Key, TTL ve database index

docker exec -it redis-lab redis-cli

Prompt açılır.

SET training:session:student-7 active EX 120
TTL training:session:student-7
GET training:session:student-7
EXISTS training:session:student-7

`SET key value EX seconds` tek komutta TTL koyar. TTL 0–120 arası saniye döner (geçen süreye bağlı); `GET` active, `EXISTS` 1 beklenir.

SELECT 1
SET training:sample one
GET training:sample
SELECT 0
GET training:sample

DB 1'de `one`, DB 0'da `(nil)` beklenir. Bu eğitimde varsayılan DB 0'a dönün.

DEL training:session:student-7
QUIT

`DEL` için integer 1/0, sonra bağlantı kapanması beklenir.

D. redis.conf ile ayar dosyası kullanma

port 6379
appendonly yes
dir /data

Bu eğitim dosyası yalnızca port, AOF ve veri dizinini tanımlar; diğer Redis ayarları varsayılan kalır. Parola gibi secret'ları dosyaya/Git'e koymayın.

Aynı servisin volumes listesine mevcut data volume'unun altına ./redis.conf:/usr/local/etc/redis/redis.conf:ro satırını ekleyin. Host dosya yolu, Compose dosyasına göreli olarak değerlendirilir.

docker compose up -d --force-recreate redis

Container yeniden oluşturulur, named volume korunur. `docker compose logs --tail 30 redis` ile config parse error olmadığını kontrol edin.

5. Beklenen çıktılar

Compose `redis-lab` Up; logs'ta sunucu hazır; PING PONG. `TTL` pozitif saniye değeri, `GET` `active`, DB 1'deki key DB 0'da nil.

7. Mini alıştırmalar

Kolay

`TTL` -1 ve -2 ne demektir?

Orta

Compose'da `127.0.0.1:6380:6379` hangi iki portu eşler?

Zor

Redis Cluster'a geçerken uygulama `SELECT 2` kullanıyorsa ne yapılmalı?

Cevap anahtarını aç/kapat
  1. -1 key var ama expiration yok; -2 key yok.
  2. Host loopback 6380 → container 6379.
  3. Logical DB bağımlılığını DB 0'a taşıyın; key prefix/ACL ile alan ayrımını tasarlayın. Cluster'da DB 0 dışında kullanılamaz.
