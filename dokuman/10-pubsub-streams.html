Redis and the Pub/Sub Model

Sayfa 10 / 13Tahmini süre: 90 dkSeviye: OrtaEğitim süresi: [X gün / Y saat]

Bu sayfa bağımsız HTML'dir; internet bağlantısı gerektirmez. Eğitim lab dosyaları redis-egitimi/docker/, redis-egitimi/python/ ve redis-egitimi/labs/ altında tutulur.

1. Öğrenme hedefleri

  • Pub/Sub fan-out ve teslim semantiğini açıklamak
  • Streams ve consumer group ile Pub/Sub'u kıyaslamak
  • Python publisher/subscriber uygulaması çalıştırmak
  • Mesaj kaybı ve ack gereksinimine göre seçim yapmak

Bu sayfaya başlamadan önce hazır olması gerekenler

Python venv/redis-py ve Redis Compose servisi hazır. İki terminal/VS Code terminal paneli kullanabilmeli.

2. Eğitmen notu

Sınıfa açılış ve aktarım dili

“Canlı bildirim ile dayanıklı iş kuyruğu aynı ihtiyaç değil. Subscriber çevrimdışıyken mesajı kaçırması sorun değilse Pub/Sub; sonradan tüketim, ack ve yeniden işleme gerekiyorsa Streams'i düşünelim.”

Sorulabilecek sorular
  • Subscriber çalışmıyorken publish edilen Pub/Sub mesajı sonra alınır mı?
  • Consumer group ack etmezse Stream mesajı ne olur?
  • Birden çok consumer aynı mesajı mı yoksa farklı mesajları mı alır?
Sınıf içi tuzaklar

Pub/Sub delivery at-most-once ve subscriber'lar online değilse mesaj kaybolur. Streams'te XACK retention/silme demek değildir. Consumer group PEL büyüyebilir; abandoned pending entries için reclaim politikası gerekir.

3. Kavramsal anlatım: neden → nedir → nasıl

Neden?

E-ticaret uygulamasında fiyat değişikliği anında dashboard'a duyurulabilir; kritik sipariş işleme için subscriber kısa süre offline olsa bile olayın saklanması gerekir. Bu iki durum aynı mesajlaşma semantiğini istemez.

Nedir?

Redis Pub/Sub channel üzerinden yayın yapar; subscriber'lar o an dinliyorsa mesajı alır, backlog yoktur. Redis Stream kayıtları ID ile saklar; consumer group load distribution, pending list ve ack sağlar. Stream retention/trim politikası ayrıca ayarlanır.

Nasıl?

Python script'i mode argümanıyla `sub` veya `pub` seçer. İki terminalde subscriber önce başlar, publisher sonra publish eder. Streams CLI demo XADD/group/read/ack ile tekrar okunabilir durable record modelini gösterir.

UZMAN NOTU · Üretim, performans ve güvenlik

Pub/Sub subscriber backpressure/slow consumer ve reconnect gap yönetmez; critical events için durable broker/Stream/outbox düşünün. Streams retention memory'yi sınırlar; trimming pending mesajları etkileyebilir. Consumer idempotency ve dedupe gerekir; Redis ack iş mantığı commit'iyle atomik değilse tekrar/çift uygulama riski vardır.

4. Adım adım uygulama (Lab)

Her checkbox sayfa içi ilerleme içindir; durum kaydedilmez. Komutları verilen sırayla uygulayın. Kod bloklarının sağ üstündeki Kopyala düğmesi içeriği panoya alır.

from __future__ import annotations

import os
import sys

import redis


def main() -> None:
    if len(sys.argv) != 2 or sys.argv[1] not in {"sub", "pub"}:
        raise SystemExit("Usage: python pubsub_demo.py sub|pub")
    client = redis.Redis.from_url(
        os.getenv("REDIS_URL", "redis://localhost:6379/0"),
        decode_responses=True,
        socket_connect_timeout=2,
        socket_timeout=2,
    )
    try:
        if sys.argv[1] == "sub":
            pubsub = client.pubsub()
            pubsub.subscribe("training:product-events")
            print("Listening on training:product-events (Ctrl+C to stop)")
            for message in pubsub.listen():
                if message["type"] == "message":
                    print("Received:", message["data"])
        else:
            count = client.publish(
                "training:product-events",
                "product:42:price-updated",
            )
            print("Subscribers reached:", count)
    finally:
        client.close()


if __name__ == "__main__":
    main()

Mode argument validates command; subscriber opens PubSub and listens; publisher returns number of subscribers reached; always close pool on process exit. VS Code run or terminal executes below.

python pubsub_demo.py sub

`Listening ...` beklenir; süreç açık kalır.

python pubsub_demo.py pub

`Subscribers reached: 1` ve Terminal 1'de `Received: product:42:price-updated` beklenir. Count 0 ise subscriber hazır değil.

Abone yokken count 0; eski mesaj subscriber'a sonradan ulaşmaz.

docker exec -it redis-lab redis-cli
XADD training:events * type price-updated product_id 42
XGROUP CREATE training:events catalog-workers 0 MKSTREAM
XREADGROUP GROUP catalog-workers worker-1 COUNT 1 STREAMS training:events >

Stream ID ve event; consumer group yeni mesajı döndürür. `XACK training:events catalog-workers <ID>` ile gerçek çıktıda ID'yi kopyalayıp ack edin.

5. Beklenen çıktılar

Subscriber önce başlatıldığında publisher `Subscribers reached: 1`; subscriber Received mesajı. Abone yokken count 0 ve backlog yoktur. Stream readgroup kaydı döner, ack PEL'den çıkarır.
