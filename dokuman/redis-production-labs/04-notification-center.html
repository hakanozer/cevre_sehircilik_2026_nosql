Notification Center

Hızlı kullanıcıya özel bildirim görünümüyle kalıcı bildirim geçmişini birbirine karıştırmayın.

Önerilen geliştirme · Bildirim modeli/controller mevcut değil

A · Problem ve B · Redis’in rolü

Ürün olayı sonrası binlerce kullanıcının bildirimini HTTP isteği içinde üretmek gecikmeyi artırır. Tek instance in-memory listesi restart/instance değişiminde kaybolur. SQLite yeni bildirim tablosu kalıcı geçmişin doğruluk kaynağı olur; Redis Sorted Set son bildirim sırası ve unread counter’ı hızlandırır. Stream producer-consumer ayrımına yardımcıdır, ancak retention/ack yönetimi gerekir. Redis ephemeral state ve hızlı index; tek başına durable inbox, exactly-once delivery ya da çevrimdışı mesaj garantisi değildir. SQLite multi-instance concurrent writes için sınırlıdır.

C · Redis veri yapıları

Sorted Set: notification ID member, created timestamp score; ZREVRANGE ile son kayıtlar.
Hash: küçük notification payload cache’i; kalıcı kopya SQLite’ta. Hash key TTL/eviction belirlenir.
Stream: producer/consumer işleri ve consumer group ack; online push için SignalR ayrıca paket ve bağlantı altyapısı ister.
KeyTip / amaçTTL / kapsam / tutarlılık
notification:user:{userId}:recentSorted Set; son ID’ler, score=UTC timestampSon N ile trim veya cache policy; userId claim; SQLite history authoritative.
notification:item:{notificationId}Hash payload cacheKısa cache TTL; notificationId global; kayıp halinde SQLite’dan yükle.
notification:stream:eventsStream event queueRetention/maxlen policy, consumer group pending/ack yönetimi; kalıcı DB’nin yerine geçmez.

D · Endpoint tasarımı

Tamamı Önerilen geliştirme; yeni tablo EF migration ile eklenmeli. İstemci userId almamalı. NoteController.GetAll tüm notları döndürür ve Create body’den UserId alır; bildirim endpoint’inde aynı sahiplik hatası yapılmamalı.

Dosya yolu: RestApi/Services/NotificationService.cs · Önerilen geliştirme

using System;
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using RestApi.Data;
using RestApi.Models;
using RestApi.Models.Dto;
using StackExchange.Redis;

namespace RestApi.Services;

public sealed class NotificationService(
    ApplicationDbContext context, IConnectionMultiplexer multiplexer)
    : INotificationService
{
    private readonly IDatabase _redis = multiplexer.GetDatabase();

    public async Task<NotificationResponseDto> CreateAsync(
        int userId, CreateNotificationRequestDto request, CancellationToken ct)
    {
        var item = new Notification
        {
            UserId = userId, Type = request.Type,
            Title = request.Title, Message = request.Message,
            CreatedAtUtc = DateTime.UtcNow
        };
        context.Notifications.Add(item);
        await context.SaveChangesAsync(ct);

        try
        {
            var recent = (RedisKey)NotificationRedisKeys.Recent(userId);
            await _redis.SortedSetAddAsync(recent, item.Id.ToString(),
                new DateTimeOffset(item.CreatedAtUtc).ToUnixTimeMilliseconds());
            await _redis.SortedSetRemoveRangeByRankAsync(recent, 0, -101);
            await _redis.KeyExpireAsync(recent, TimeSpan.FromDays(7));
            var itemKey = (RedisKey)NotificationRedisKeys.Item(item.Id);
            await _redis.HashSetAsync(itemKey, new[]
            {
                new HashEntry("title", item.Title),
                new HashEntry("message", item.Message),
                new HashEntry("read", "false")
            });
            await _redis.KeyExpireAsync(itemKey, TimeSpan.FromDays(1));
        }
        catch (RedisException ex)
        {
            // SQL commit already succeeded; caller must not assume it rolled back.
            throw new NotificationStoreUnavailableException(ex);
        }

        return Map(item);
    }

    public async Task<IReadOnlyList<NotificationResponseDto>> GetRecentAsync(
        int userId, int count, CancellationToken ct)
    {
        count = Math.Clamp(count, 1, 100);
        RedisValue[] ids;
        try
        {
            ids = await _redis.SortedSetRangeByRankAsync(
                NotificationRedisKeys.Recent(userId), 0, count - 1,
                Order.Descending);
        }
        catch (RedisException ex)
        {
            throw new NotificationStoreUnavailableException(ex);
        }

        if (ids.Length == 0)
        {
            var latest = await context.Notifications.AsNoTracking()
                .Where(n => n.UserId == userId)
                .OrderByDescending(n => n.CreatedAtUtc)
                .Take(count).ToListAsync(ct);
            try
            {
                var key = (RedisKey)NotificationRedisKeys.Recent(userId);
                foreach (var item in latest)
                    await _redis.SortedSetAddAsync(key, item.Id.ToString(),
                        new DateTimeOffset(item.CreatedAtUtc).ToUnixTimeMilliseconds());
                await _redis.KeyExpireAsync(key, TimeSpan.FromDays(7));
                ids = latest.Select(n => (RedisValue)n.Id.ToString()).ToArray();
            }
            catch (RedisException ex)
            {
                throw new NotificationStoreUnavailableException(ex);
            }
        }

        var parsedIds = ids.Select(x => int.TryParse(x.ToString(), out var id) ? id : 0)
            .Where(id => id > 0).ToArray();
        var rows = await context.Notifications.AsNoTracking()
            .Where(n => n.UserId == userId && parsedIds.Contains(n.Id))
            .ToDictionaryAsync(n => n.Id, ct);
        return parsedIds.Where(rows.ContainsKey).Select(id => Map(rows[id])).ToArray();
    }

    public async Task<bool> MarkReadAsync(
        int userId, int notificationId, CancellationToken ct)
    {
        var item = await context.Notifications
            .SingleOrDefaultAsync(n => n.Id == notificationId && n.UserId == userId, ct);
        if (item is null) return false;
        if (item.ReadAtUtc is null)
        {
            item.ReadAtUtc = DateTime.UtcNow;
            await context.SaveChangesAsync(ct);
            try
            {
                await _redis.HashSetAsync(NotificationRedisKeys.Item(item.Id),
                    "read", "true");
                await _redis.KeyExpireAsync(
                    NotificationRedisKeys.Item(item.Id), TimeSpan.FromDays(1));
            }
            catch (RedisException ex)
            {
                throw new NotificationStoreUnavailableException(ex);
            }
        }
        return true;
    }

    private static NotificationResponseDto Map(Notification n) =>
        new(n.Id, n.Type, n.Title, n.Message, n.CreatedAtUtc, n.ReadAtUtc);
}

SQLite is authoritative for history/read state; Redis Sorted Set is rebuildable index, Hash is short cache. DB commit and Redis writes are not atomic: Redis failure is explicit 503 even though create/read may already be persisted; retry can duplicate create unless idempotency is added. Production repair should rebuild index/outbox, not assume rollback.

Bu adımda sık yapılan hata: Redis hata verdi diye SQL commit olmadı sanıp blind retry yapmak. Kalıcı row already exists; use idempotency/outbox and reconciliation for reliable delivery.

7. Controller

Dosya yolu: RestApi/Controllers/NotificationsController.cs · Önerilen geliştirme

using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using RestApi.Models.Dto;
using RestApi.Services;
using StackExchange.Redis;

namespace RestApi.Controllers;

[ApiController]
[Route("api/notifications")]
[Authorize]
public sealed class NotificationsController(INotificationService service)
    : ControllerBase
{
    private bool TryUserId(out int id) =>
        int.TryParse(User.FindFirstValue(ClaimTypes.NameIdentifier), out id) && id > 0;

    [HttpPost]
    public async Task<IActionResult> Create(
        CreateNotificationRequestDto request, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        try { return StatusCode(201, await service.CreateAsync(userId, request, ct)); }
        catch (NotificationStoreUnavailableException)
        { return StatusCode(503, new ProblemDetails { Status=503, Title="Notification index unavailable; database write may have completed." }); }
    }

    [HttpGet]
    public async Task<IActionResult> Recent(
        [FromQuery] int count = 20, CancellationToken ct = default)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        if (count is < 1 or > 100) return BadRequest();
        try { return Ok(await service.GetRecentAsync(userId, count, ct)); }
        catch (NotificationStoreUnavailableException)
        { return StatusCode(503, new ProblemDetails { Status=503, Title="Notification index unavailable." }); }
    }

    [HttpPost("{id:int}/read")]
    public async Task<IActionResult> Read(int id, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        try { return await service.MarkReadAsync(userId, id, ct) ? NoContent() : NotFound(); }
        catch (NotificationStoreUnavailableException)
        { return StatusCode(503, new ProblemDetails { Status=503, Title="Notification index unavailable; read state may be saved." }); }
    }
}

POST create 201, GET 200, mark read 204, DTO invalid 400, unauthenticated 401, other user’s ID 404, Redis unavailable 503. Existing roles are Product/Note; this sample requires any authenticated user, not nonexistent Notification/Admin roles.

Bu adımda sık yapılan hata: Query/body userId ile başka kullanıcı bildirimini listelemek veya değiştirmek. NoteController’daki gerçek eksik sahiplik kontrolünü tekrar etmeyin.

9. Son kontrol

Bu adımda sık yapılan hata: Final doğrulamayı atlayıp yalnızca başarılı HTTP yanıtına güvenmek; kalıcı DB state’i, Redis key’i ve hata senaryosunu birlikte kontrol edin.

E · Uygulama adımları

  1. Notification entity + migration: owner, type, payload/reference, createdAt, readAt; minimal kişisel payload. Verify ownership FK/index and rollback migration.
  2. NotificationService ve controller: SQLite kalıcı yazım, sonra Redis index/counter update. DB commit ile Redis update atomik değil; outbox veya repair/rebuild seçeneğini değerlendir.
  3. Producer event’i Stream’e yaz, BackgroundService consumer group ile işle, ack sonrası completed; pending reclaim ve idempotent event ID ekle.
  4. SignalR seçilirse ek paket/Hub ve bağlantı authorization’ı gerekir; Pub/Sub kalıcı kuyruk değildir.

.NET örneği · önerilen NotificationsService.cs

public sealed class NotificationsService(
    IConnectionMultiplexer mux, ApplicationDbContext db)
{
    public async Task<int> AddRecentIdAsync(int userId, int notificationId, long score)
    {
        var key = (RedisKey)$"notification:user:{userId}:recent";
        var added = await mux.GetDatabase().SortedSetAddAsync(
            key, notificationId.ToString(), score);
        return added ? 1 : 0;
    }
}

Entity persistence, transaction, ownership and retry are intentionally omitted from this focused Redis fragment. Register service with AddScoped; DbContext is scoped.

F · İstek akışı / hata akışları

HTTP → ErrorHandlerMiddleware → GlobalMiddleware → Authentication → Authorization → NotificationsController → Service → SQLite commit → Redis index/cache (or Stream producer)
Başarılı: notification row committed → per-user sorted set indexed → response ID.
Hata: DB commit succeeded, Redis write failed → notification remains in SQLite; return policy plus retry/rebuild path. Do not report it never existed.

Production notları / çıktılar

Sorted Set order, Hash field cache, Streams consumer group, owner claim and durable-vs-ephemeral split. Keep old notifications in SQLite; trim Redis index deliberately. Payload privacy, unread counter races, retries and dead letters matter. Prerequisite: none; Modül 08 covers workers.

Görevler

  1. Recent IDs sorted query.
    İpucuUse score timestamp and bounded range; cursor tie-break for same timestamp.
  2. Persist unread row and counter.
    İpucuDatabase is source of truth; recovery rebuilds Redis.
  3. Simulate consumer crash before ack.
    İpucuPending entry can be reclaimed; event handler must be idempotent.

Checklist / kendini değerlendir

Yanıtları göster

1) ZSet score neden? Sıralama/pagination. 2) Redis kaybında geçmiş? SQLite’dan tekrar kurulur. 3) Pub/Sub offline teslim eder mi? Hayır. 4) Stream exactly-once mi? Hayır; at-least-once benzeri işleme/ack akışı ve idempotency gerekir.

Sık yapılan hatalar

  • Bildirimleri yalnızca Redis’te tutmak → gereken geçmişi SQLite’ta kalıcılaştır.
  • Stream ack öncesi yan etkiyi tekrar çalıştırmak → idempotent event handler.
  • İstemciden owner ID almak → JWT NameIdentifier kullan.
