Stok Rezervasyonu ve Dağıtık Kilitleme

Fazla satış riskini ve kilit protokolünün sınırlarını ayırın.

Mevcut projeden doğrulandı: Product.Id/Price · Stok alanı, sipariş ve endpoint öneridir

A · Problem / B · Redis seçimi

Son ürüne aynı anda iki istek geldiğinde önce okuyup sonra yazma (read-then-write) fazla satışa yol açabilir. Uygulama içi kilit farklı instance’ları koordine etmez. Redis Lua stok değerini okuyup azaltmayı Redis içinde atomik yapabilir; rezervasyon TTL’i terk edilmiş tutmaları sınırlar. Ancak mevcut Product modelinde Stock yok; SQLite’a stok kolonu/tablosu, migration ve DB kısıtları gerekir. SQLite kalıcı doğruluk kaynağıdır; Redis Lua ile SQLite transaction arasında dağıtık transaction kurulmaz. SQLite tek dosyası çok instance’lı eşzamanlı yazma için sınırlıdır. Kampanya hakkı gibi tek kullanımlık işlem de yalnız kilit değil kalıcı unique constraint ister.

C · Redis özellikleri ve key’ler

E · Adım adım tasarım

  1. Stock alanı/tablosunu migration ile ekle; check constraint ve concurrency token değerlendir. DB’de doğrudan eşzamanlı update test et.
  2. Doğruluk kaynağını belirle: SQLite transaction içindeki koşullu UPDATE en basit otoritatif yol olabilir. Redis rezervasyonu koordinasyon projeksiyonuyla uzlaştırılmalıdır.
  3. Redis kilidinde kriptografik sahip token’ı üret; SET key token NX PX leaseMs, sınırlı retry/jitter; compare-and-delete script. Kilit süresi/GC pause çakışmaya yol açabilir; fencing token veya DB koşullu update gerekir.
  4. Rezervasyon expiry yalnızca Redis key’in kaybolması değildir; sweeper/uzlaştırma SQLite’taki eski rezervasyonları yönetir.

1. Hazırlık

Mevcut projeden doğrulandı: Product has Id/Name/Price only; Redis multiplexer and EF Core SQLite are already configured. No package needed.

Bu adımda sık yapılan hata: Redis lock acquired diye stock is guaranteed. Lease can expire; conditional SQLite update is the actual no-oversell guard.

Dosya yolu: RestApi/Services/IInventoryService.cs · Önerilen geliştirme

using System.Threading;
using System.Threading.Tasks;
using RestApi.Models.Dto;
namespace RestApi.Services;
public interface IInventoryService
{
    Task<ReservationResponseDto> ReserveAsync(int userId, int productId, int quantity, CancellationToken ct);
    Task<bool> ReleaseAsync(int userId, int reservationId, CancellationToken ct);
}

Dosya yolu: RestApi/Services/InventoryService.cs · Önerilen geliştirme

using System;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using RestApi.Data;
using RestApi.Models;
using RestApi.Models.Dto;
using StackExchange.Redis;
namespace RestApi.Services;
public sealed class InventoryService(
    ApplicationDbContext context, IConnectionMultiplexer multiplexer) : IInventoryService
{
    private readonly IDatabase _redis = multiplexer.GetDatabase();
    public async Task<ReservationResponseDto> ReserveAsync(
        int userId, int productId, int quantity, CancellationToken ct)
    {
        var key = (RedisKey)InventoryRedisKeys.Lock(productId);
        var token = Guid.NewGuid().ToString("N");
        if (!await _redis.LockTakeAsync(key, token, TimeSpan.FromSeconds(10)))
            throw new InventoryLockBusyException();
        try
        {
            await using var tx = await context.Database.BeginTransactionAsync(ct);
            var changed = await context.Products.Where(p => p.Id == productId && p.Stock >= quantity)
                .ExecuteUpdateAsync(s => s.SetProperty(p => p.Stock, p => p.Stock - quantity), ct);
            if (changed == 0)
            {
                if (!await context.Products.AnyAsync(p => p.Id == productId, ct))
                    throw new ProductNotFoundException();
                throw new InsufficientStockException();
            }
            var row = new Reservation { UserId = userId, ProductId = productId, Quantity = quantity };
            context.Reservations.Add(row);
            await context.SaveChangesAsync(ct);
            await tx.CommitAsync(ct);
            return new ReservationResponseDto(row.Id, productId, quantity, row.Status);
        }
        finally
        {
            await _redis.LockReleaseAsync(key, token);
        }
    }

    public async Task<bool> ReleaseAsync(int userId, int reservationId, CancellationToken ct)
    {
        var row = await context.Reservations.SingleOrDefaultAsync(
            r => r.Id == reservationId && r.UserId == userId, ct);
        if (row is null) return false;
        if (row.Status == "Released") return true;
        var key = (RedisKey)InventoryRedisKeys.Lock(row.ProductId);
        var token = Guid.NewGuid().ToString("N");
        if (!await _redis.LockTakeAsync(key, token, TimeSpan.FromSeconds(10)))
            throw new InventoryLockBusyException();
        try
        {
            await using var tx = await context.Database.BeginTransactionAsync(ct);
            row = await context.Reservations.SingleAsync(
                r => r.Id == reservationId && r.UserId == userId, ct);
            if (row.Status == "Reserved")
            {
                await context.Products.Where(p => p.Id == row.ProductId)
                    .ExecuteUpdateAsync(s => s.SetProperty(p => p.Stock, p => p.Stock + row.Quantity), ct);
                row.Status = "Released";
                await context.SaveChangesAsync(ct);
            }
            await tx.CommitAsync(ct);
            return true;
        }
        finally { await _redis.LockReleaseAsync(key, token); }
    }
}

SQLite conditional stock update is authoritative; Redis lock only reduces contention. Redis exceptions propagate and controller returns 503; if failure happens after SQL commit (e.g. lock release), reservation may already exist. A lease expiry still allows two lock holders, but conditional SQL update prevents oversell. Add expiry/sweeper and stronger concurrency policy before production.

Bu adımda sık yapılan hata: Lock release exception silently swallowed or assuming transaction rollback after commit. Report uncertainty and reconcile durable reservation state.

7. Controller

Dosya yolu: RestApi/Controllers/InventoryController.cs · Önerilen geliştirme

using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using RestApi.Models.Dto;
using RestApi.Services;
using StackExchange.Redis;
namespace RestApi.Controllers;
[ApiController]
[Route("api/inventory")]
[Authorize]
public sealed class InventoryController(IInventoryService service) : ControllerBase
{
    private bool TryUserId(out int id) =>
        int.TryParse(User.FindFirstValue(ClaimTypes.NameIdentifier), out id) && id > 0;
    [HttpPost("{productId:int}/reservations")]
    public async Task<IActionResult> Reserve(int productId, ReserveInventoryDto request, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        if (productId <= 0) return BadRequest();
        try { return StatusCode(201, await service.ReserveAsync(userId, productId, request.Quantity, ct)); }
        catch (ProductNotFoundException) { return NotFound(); }
        catch (InsufficientStockException) { return Conflict(new ProblemDetails { Title="Insufficient stock." }); }
        catch (InventoryLockBusyException) { return Conflict(new ProblemDetails { Title="Inventory is being updated; retry." }); }
        catch (RedisException) { return StatusCode(503); }
    }
    [HttpDelete("reservations/{id:int}")]
    public async Task<IActionResult> Release(int id, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        try { return await service.ReleaseAsync(userId, id, ct) ? NoContent() : NotFound(); }
        catch (InventoryLockBusyException) { return Conflict(); }
        catch (RedisException) { return StatusCode(503); }
    }
}

Reserve 201; missing product 404; insufficient stock/lock busy 409; malformed quantity 400; anonymous 401; Redis unavailable 503. Release is owner-scoped (204 / 404), repeat release 204.

Bu adımda sık yapılan hata: Reservation ID endpoint without owner filter. Every lookup includes claim-derived userId.

.NET örneği · önerilen kilit servisi

using StackExchange.Redis;

public sealed class InventoryLockService(IConnectionMultiplexer mux)
{
    public Task<bool> TryAcquireAsync(int productId, string ownerToken) =>
        mux.GetDatabase().StringSetAsync(
            $"lock:inventory:product:{productId}",
            ownerToken, TimeSpan.FromSeconds(5), When.NotExists);
}

Controller bir sahip token’ı üretip bu metodu çağırır; bırakma compare-token Lua ile yapılır. Kayıtlı singleton multiplexer ve scoped DbContext kullan; Redis kilidi SQLite commit’ini Redis ile atomik hale getirmez.

F · Akış, production, öğrenme çıktıları

HTTP → ErrorHandlerMiddleware → GlobalMiddleware → Authentication → Authorization → ReservationController → Redis Lua/SET NX lease → SQLite transaction/constraint → yanıt
Başarı: stok yeterli, koşullu DB geçişi başarılı, rezervasyon kaydedilmiş ve confirm tekrarı idempotent.
Hata: duraklama sırasında lease süresi dolar; başka çağıran kilidi alır. Eski çağıranın DB update’i version/fencing/koşulla reddedilmeli; eski sahip yeni kilidi bırakamamalı.
  • Lua yalnız Redis içinde atomik; Redis/SQLite transaction yok.
  • Redlock tartışması kapsamlıdır; bu lab tek Redis instance varsayar. Lease DB constraint/fencing’in yerine geçmez.
  • Redis restart/eviction rezervasyon state’ini kaybettirebilir; SQLite ile uzlaştır.
  • Reserve/release idempotent tasarla; başarı sonrası timeout retry için güvenli olmalı.
  • TTL tam zamanda silinme garantisi değildir; rezervasyon için açık expiry politikası gerekir.

Çıktılar: SET NX PX, sahip güvenli release, lease/fencing, DB doğruluk sınırı. Önkoşul Modül 09 Idempotency. Stock alanı yok; yalnız önerilen migration ile eklenebilir.

Kendini değerlendir · yanıtlar

1) Lua SQLite’ta da atomik mi? Hayır. 2) Sahip token’ı neden? Sonraki sahibin kilidini silmemek. 3) Lease expiry riski? İşler çakışabilir; fencing/DB koşullu update gerekir. 4) Mevcut stok kaynağı? Stock yok; migration öneridir.

Sık yapılan hatalar

  • Product’ta Stock var sanmak → yok; şema eklemek öneridir.
  • Kilidi düz DEL ile bırakmak → sahipliği atomik karşılaştır.
  • Redis kilidini stok doğruluğu sanmak → DB koşulu/constraint otoritatiftir.
