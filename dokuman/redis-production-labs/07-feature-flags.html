Feature Flags

Uygulama deploy etmeden bir özelliği kontrollü açıp kapatın; feature flag’i authorization sanmayın.

Önerilen geliştirme · Flag yönetim endpoint’i/Admin rolü yok

A · Problem / B · Redis neden?

Statik appsettings değişikliği çoğu zaman uygulama restart/deploy ister ve instance’lar arasında farklılaşabilir. Merkezi Redis flag’i birden çok instance’ın aynı değeri görmesine yardım eder. String basit flag; Hash segment, rollout yüzdesi ve metadata tutabilir. Pub/Sub hızlı invalidation signal verir ama offline subscriber mesajı kaçırır ve kalıcı kuyruk değildir; per-request read veya version/poll strategy gerekir. Redis outage’da güvenli default seçin. Feature flag rollout/operational control’dür, authorization değildir. SQLite config/control record için kalıcı kaynak olabilir; Redis tek başına audit history sağlamaz.

Mevcut appsettings.json statiktir; product cache code path’i flag ile sarılabilir, örn. products:cache-enabled. Cache disabled modu Module 12’de test edilir.

D · Endpoint tasarımı

Örnekler Önerilen geliştirme. Yeni Admin role/policy yok; product controller’da Product rolü mevcut. Admin endpoint’i için rol değeri User.Role alanına eklenebilir veya AddAuthorization policy ile yönetilebilir; bu değişiklikler gerçek uygulamada henüz yok.

E · Uygulama, komut ve kod

  1. Define flag registry, owner, safe default, expiry/removal date; clean stale flags.
  2. Flag reader service uses shared singleton multiplexer; cache local copy with short refresh or version notification. Multi-instance propagation measured.
  3. Admin change requires explicit role/policy, validation, audit and staged rollout; flag must never replace API authorization.
  4. Pub/Sub notification accelerates cache invalidation but subscriber restart must reload authoritative value.

1. Hazırlık

Mevcut projeden doğrulandı: .NET 9, SQLite EF Core, StackExchange.Redis 3.3.1 and singleton multiplexer exist. No package required. Redis start: docker compose up -d redis.

Bu adımda sık yapılan hata: Feature flag’i authorization yerine kullanmak. Flag never grants access to protected resources.

using System;
using System.Text.RegularExpressions;
namespace RestApi.Services;
public static class FeatureFlagRedisKeys
{
    public static string Flag(string name) =>
        Regex.IsMatch(name, "^[a-z0-9-]{1,80}$")
            ? $"feature:flag:{name}"
            : throw new ArgumentException("Invalid flag name.", nameof(name));
}

Bu adımda sık yapılan hata: Unbounded arbitrary client strings become keys. Validate slug syntax and keep a known flag registry.

using RestApi.Models.Dto;
namespace RestApi.Services;

Dosya yolu: RestApi/Services/FeatureFlagService.cs · Önerilen geliştirme

using System;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using RestApi.Data;
using RestApi.Models;
using RestApi.Models.Dto;
using StackExchange.Redis;
namespace RestApi.Services;
public sealed class FeatureFlagService(
    ApplicationDbContext context, IConnectionMultiplexer multiplexer)
    : IFeatureFlagService
{
    private readonly IDatabase _redis = multiplexer.GetDatabase();

    public async Task<FeatureFlagResultDto?> GetAsync(
        string name, int userId, CancellationToken ct)
    {
        var key = (RedisKey)FeatureFlagRedisKeys.Flag(name);
        FeatureFlag? flag = null;
        try
        {
            var values = await _redis.HashGetAllAsync(key);
            if (values.Length > 0)
            {
                var enabled = values.FirstOrDefault(x => x.Name == "enabled").Value;
                var percent = values.FirstOrDefault(x => x.Name == "percent").Value;
                if (bool.TryParse(enabled.ToString(), out var on) &&
                    int.TryParse(percent.ToString(), out var rollout))
                    flag = new FeatureFlag { Name = name, Enabled = on, RolloutPercentage = rollout };
            }
        }
        catch (RedisException)
        {
            // SQLite is authoritative: continue with source-of-truth lookup.
        }
        flag ??= await context.FeatureFlags.AsNoTracking()
            .SingleOrDefaultAsync(x => x.Name == name, ct);
        if (flag is null) return null;

        try
        {
            await _redis.HashSetAsync(key, new[]
            {
                new HashEntry("enabled", flag.Enabled.ToString().ToLowerInvariant()),
                new HashEntry("percent", flag.RolloutPercentage.ToString())
            });
            await _redis.KeyExpireAsync(key, TimeSpan.FromMinutes(2));
        }
        catch (RedisException)
        {
            // Cache is optional on reads; return authoritative DB result.
        }
        var bucket = (int)(unchecked((uint)userId * 2654435761u) % 100);
        return new FeatureFlagResultDto(name, flag.Enabled, flag.RolloutPercentage,
            flag.Enabled && bucket < flag.RolloutPercentage);
    }

    public async Task SetAsync(string name, SetFeatureFlagDto request, CancellationToken ct)
    {
        _ = FeatureFlagRedisKeys.Flag(name);
        var flag = await context.FeatureFlags.SingleOrDefaultAsync(x => x.Name == name, ct);
        if (flag is null) context.FeatureFlags.Add(flag = new FeatureFlag { Name = name });
        flag.Enabled = request.Enabled;
        flag.RolloutPercentage = request.RolloutPercentage;
        flag.UpdatedAtUtc = DateTime.UtcNow;
        await context.SaveChangesAsync(ct);
        var key = (RedisKey)FeatureFlagRedisKeys.Flag(name);
        await _redis.HashSetAsync(key, new[]
        {
            new HashEntry("enabled", flag.Enabled.ToString().ToLowerInvariant()),
            new HashEntry("percent", flag.RolloutPercentage.ToString())
        });
        await _redis.KeyExpireAsync(key, TimeSpan.FromMinutes(2));
    }
}

Read is fail-safe to SQLite on Redis errors; set saves SQLite first, then Redis failure surfaces (request may have persisted). The two-minute TTL bounds stale values on other instances. Production admin changes should also publish invalidation/audit an actor, and cache misses naturally reload DB.

Bu adımda sık yapılan hata: Redis cache invalidation as durable audit. SQL remains source-of-truth; capture actor and change history separately if required.

7. Controller

Dosya yolu: RestApi/Controllers/FeatureFlagsController.cs · Önerilen geliştirme

using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using RestApi.Models.Dto;
using RestApi.Services;
using StackExchange.Redis;
namespace RestApi.Controllers;
[ApiController]
[Route("api/feature-flags")]
[Authorize]
public sealed class FeatureFlagsController(IFeatureFlagService service) : ControllerBase
{
    private bool TryUserId(out int id) =>
        int.TryParse(User.FindFirstValue(ClaimTypes.NameIdentifier), out id) && id > 0;

    [HttpGet("{name}")]
    public async Task<IActionResult> Get(string name, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        try
        {
            var result = await service.GetAsync(name, userId, ct);
            return result is null ? NotFound() : Ok(result);
        }
        catch (ArgumentException) { return BadRequest(); }
    }

    [HttpPut("{name}")]
    [Authorize(Roles = "Admin")]
    public async Task<IActionResult> Set(
        string name, SetFeatureFlagDto request, CancellationToken ct)
    {
        if (!TryUserId(out _)) return Unauthorized();
        try { await service.SetAsync(name, request, ct); return NoContent(); }
        catch (ArgumentException) { return BadRequest(); }
        catch (RedisException) { return StatusCode(503, new ProblemDetails { Title="Flag saved to SQLite; Redis refresh failed." }); }
    }
}

GET 200/404, PUT 204, invalid DTO/name 400, anonymous 401, missing Admin role 403, Redis write failure 503 though DB may be saved. Provision Admin on an account before running PUT; no seeded Admin role is assumed.

Bu adımda sık yapılan hata: Assuming Admin already exists or allowing all users to change flags. Configure role assignment out-of-band and retain API authorization independently.

Bu adımda sık yapılan hata: Final doğrulamayı atlayıp yalnızca başarılı HTTP yanıtına güvenmek; kalıcı DB state’i, Redis key’i ve hata senaryosunu birlikte kontrol edin.

docker exec -it redis-lab redis-cli

GET feature:flag:products-cache-enabled
HSET feature:flag:search-rollout enabled true percentage 10 version 3

PUBLISH returns subscriber count, not durable delivery. Late subscriber misses event; refresh actual key.

F · Akış, riskler, öğrenme

HTTP → ErrorHandlerMiddleware → GlobalMiddleware → Authentication → Authorization (admin policy öneri) → FlagController → Redis GET/SET/PUBLISH → SQLite audit (öneri)
Success: authorized change persisted/versioned → publish signal → instances reload.
Failure: Redis unavailable → per-flag safe default and explicit alert; do not skip authorization.
  • Flag key eviction/restart can revert behavior; choose fail-safe default and source of truth.
  • Pub/Sub not queue; no offline catch-up or ack. Redis outage should not open risky feature by accident.
  • Flag proliferation creates dead branches; owner and removal date.
  • Segment evaluation needs stable userId, not username/email; rollout algorithm deterministic.

Outcomes: dynamic config, safe defaults, Pub/Sub boundary, flag vs authorization. Prior module none; Module 12 links cache flag to measurement.
