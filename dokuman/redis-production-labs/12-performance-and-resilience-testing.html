Performance & Resilience Testing

Ölçmeden hızlanma iddiası üretmeyin; cache hit/miss, outage ve tail latency’yi kıyaslayın.

Mevcut projeden doğrulandı: GET api/product · middleware · docker-compose

A · Problem / B · Ölçümün rolü

Redis cache hit’in latency’yi azalttığı varsayımı ancak gerçek workload ölçümüyle kanıtlanır. DB cache warm/cold farkı, Redis network, serializer, request logs, auth ve rate limit sonucu etkiler. Çok kısa benchmark p50’yi gösterip p95/p99 ve hata oranını saklayabilir. SQLite tek dosya multi-instance writes için sınırlı; gerçek deployment benzer topolojiyle test edilmeli. Mevcut GET api/product cache’li kıyas için uygundur; Redis disabled mode mevcut değildir (önerilen test toggle/mod). Testte cache reset, warm-up ve rate limiter durumu sabitlenmeli.

C · Ölçülecek sinyaller

HTTP: throughput, p50/p95/p99 latency, status/error rate.
Cache: hit/miss ratio, serialization, cache fill concurrency.
Redis: command latency, connected clients, memory/eviction, timeout.
DB: SQLite query count, lock/busy errors, CPU/IO.

D · Endpoint + test design

Primary endpoint GET api/product is Mevcut, class-level Product role required; Product List Postman request shows no token setup, a mismatch. Data mutation routes are real but changing shared dataset invalidates cache. Cache-off comparison needs proposed flag or separate test implementation; not an existing endpoint. Rate limiter in Program.cs currently passive; enabling it enforces 1 req/sec and invalidates load test throughput. ErrorHandlerMiddleware prints every header; GlobalMiddleware logs every request—console I/O contaminates benchmark results. Log safely and consistently for both test runs.

E · Step-by-step lab

  1. Use k6/JMeter from an authorized local environment; constant virtual users/rate, warmup and fixed test window; protect API from uncontrolled overload.
  2. Run cache warm scenario, then controlled miss; test stampede burst separately. Clear key between runs and verify TTL.
  3. Test Redis outage/timeout and recovery. Record actual status; current GET returns middleware 500, not DB fallback. Watch SQLite load.
  4. Repeat with cache bypass proposed flag only after implementing separately; compare paired runs, not incomparable cold/warm samples.
  5. Observe Redis server; docker-compose has no maxmemory/eviction config. Proposed isolated experiment may start Redis with explicit maxmemory and policy after reviewing container version/semantics.

Dosya yolu: RestApi/Services/RedisDiagnostics.cs · Önerilen geliştirme

using System;
using System.Diagnostics;
using System.Threading;
using System.Threading.Tasks;
using RestApi.Models.Dto;
using StackExchange.Redis;
namespace RestApi.Services;
public sealed class RedisDiagnostics(IConnectionMultiplexer multiplexer) : IRedisDiagnostics
{
    private readonly IDatabase _db = multiplexer.GetDatabase();
    public async Task<RedisProbeResultDto> ProbeAsync(CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested();
        var pingWatch = Stopwatch.StartNew();
        await _db.PingAsync();
        pingWatch.Stop();
        var key = (RedisKey)RedisProbeKeys.Probe(Guid.NewGuid());
        var roundTrip = Stopwatch.StartNew();
        await _db.StringSetAsync(key, "ok", TimeSpan.FromSeconds(10));
        var value = await _db.StringGetAsync(key);
        var deleted = await _db.KeyDeleteAsync(key);
        roundTrip.Stop();
        return new RedisProbeResultDto(pingWatch.ElapsedMilliseconds,
            roundTrip.ElapsedMilliseconds, value == "ok" && deleted);
    }
}

Redis exceptions propagate; the API maps them to 503. Probe latency is one sample, not a percentile or benchmark. Do not expose broad INFO/CONFIG endpoints.

Bu adımda sık yapılan hata: Treating one ping as p95 latency. Gather distributions from repeated authorized load tests.

7. Controller

Dosya yolu: RestApi/Controllers/RedisDiagnosticsController.cs · Önerilen geliştirme

using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using RestApi.Services;
using StackExchange.Redis;
namespace RestApi.Controllers;
[ApiController]
[Route("api/diagnostics/redis")]
[Authorize(Roles = "Product")]
public sealed class RedisDiagnosticsController(IRedisDiagnostics diagnostics) : ControllerBase
{
    [HttpGet]
    public async Task<IActionResult> Probe(CancellationToken ct)
    {
        if (!int.TryParse(User.FindFirstValue(ClaimTypes.NameIdentifier), out var userId)
            || userId <= 0) return Unauthorized();
        try { return Ok(await diagnostics.ProbeAsync(ct)); }
        catch (RedisException) { return StatusCode(503); }
    }
}

GET returns 200 timings, anonymous 401, no Product role 403, Redis unavailable 503. Timings are for an individual probe; product performance is measured against existing GET.

Bu adımda sık yapılan hata: Reporting Redis timing as end-to-end API latency or omitting the route’s role requirement.

F · Request flow / success & failure

HTTP → ErrorHandlerMiddleware (Console all headers) → GlobalMiddleware (Console each request) → Authentication → Authorization(Product) → ProductController → Redis GET → SQLite on miss → Redis SET → response
Success: warm key yields 200; hit ratio and tail latency measured alongside DB query count.
Failure: Redis stopped → uncaught Redis exception reaches ErrorHandlerMiddleware → 500 JSON with exception.Message. Test restoration and cold-cache surge.

G · Production considerations

  • Console writes per request and header dump skew latency and risk bearer token disclosure; test logger configuration safe and equal across scenarios.
  • Program.cs built-in rate limiter is configured but commented middleware means currently inactive. If enabled with 1 req/sec, it dominates test results. Check state before each run.
  • ConnectTimeout/SyncTimeout=5000ms can contribute delays; measure async calls and timeout distribution. Do not assume setting means every request waits exactly 5 seconds.
  • No maxmemory/eviction policy in compose. Eviction experiment requires isolated config and observations of evicted_keys, memory, hit ratio.
  • Reconnect/recovery, cold-start stampede, client retries and SQLite locking are resilience conditions.
  • Redis durability AOF enabled in compose; image version tag existence unverified. Don’t claim version-specific behavior.

Outcomes: p95/p99, throughput, cache hit ratio, latency/error correlation, fault injection and measurement discipline. Prerequisite Module 11 cache/outage.

H · Tasks / checklist

  1. Prepare reproducible warm-cache test.
    İpucuRecord commit, environment, warm-up, auth, rate limiter status.
  2. Compare cold burst with Redis warm.
    İpucuCount DB SELECTs, not just HTTP duration.
  3. Stop Redis then restore; inspect errors/DB overload.
    İpucuCurrent code has no fallback; observe exact 500 and recovery surge.
Kendini değerlendir

1) Warm cache proves cold behavior? No. 2) Why p99? Tail user impact. 3) Rate limiter effect? 1 req/sec if middleware enabled; currently passive. 4) Current Redis outage? 500, no SQLite fallback. 5) Can quote speedup without measurement? No.

Sık yapılan hatalar

  • Compare warm cache to cold DB without matching setup → paired controlled scenarios.
  • Ignore logging/rate limiting → record and normalize these confounders.
  • Report average only → p95/p99 and errors.
  • Use production token or load → isolated credentials/data and approved load envelope.
