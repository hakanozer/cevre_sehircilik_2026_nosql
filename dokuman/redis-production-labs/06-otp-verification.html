OTP Verification

Bir kullanımlık kod, yanlış deneme sınırı ve Redis kesintisinde bilinçli güvenlik davranışı.

Önerilen geliştirme · OTP/email/SMS servisi mevcut değil

A · Problem / B · Redis niçin?

Parola sıfırlama veya e-posta doğrulama kodu her API instance’ında bellekte tutulursa diğer instance doğrulayamaz; process restart kaydı siler. Redis String + TTL kodun kısa ömürlü paylaşımını ve sayaçları sağlar. TTL kodun belirli milisaniyede fiziksel silineceğini garanti etmez; server-side expiry kontrolü de gerekir. Redis kalıcı kimlik kanıtı, e-posta gönderim garantisi veya SQL transaction değildir. SQLite kullanıcı kaydı authoritative; bu uygulamada e-posta formatı UserLoginDto.Username’de var fakat OTP/email provider yok. SQLite çok instance yazma açısından sınırlı.

C · Özellikler ve key’ler

String + TTL: OTP hash’ini sınırlı süre tut.
Attempts counter: INCR + expire; atomik sayaç, account/IP limit ile birlikte.
Lua: compare, attempt count, success delete tek Redis script; SQLite transaction veya external email delivery ile atomic değil.

Tümü Önerilen geliştirme. Username e-posta biçimli; e-posta servisi dış entegrasyon olarak eklenmeli. Identities/roles mevcut: NameIdentifier, Name, Product/Note. OTP code gövdesinden asla log üretme.

E · Uygulama adımları

  1. Generate numeric code with RandomNumberGenerator, not Random; fixed width and leading zero preservation. Send only through provider.
  2. Store keyed hash/HMAC or hash with server-side secret to reduce impact if Redis read leaked; ordinary fast hash of 6 digits is enumerable, so rate limits remain essential. Choose constant-time comparison / secret lifecycle.
  3. Script validates the attempt and consumes code atomically. Separate resend/verification windows; per-account and per-IP safeguards.
  4. Audit log has correlation ID/status only; existing AuthController logs password hash, encrypted and decrypted password values; ErrorHandler logs all headers. These are explicit counterexamples to follow.

using System.Threading;
using System.Threading.Tasks;

public interface IOtpService
{
    Task IssueAsync(int userId, string email, CancellationToken ct);
    Task<bool> VerifyAsync(int userId, string code, CancellationToken ct);
}

Dosya yolu: RestApi/Services/OtpService.cs · Önerilen geliştirme

using System;
using System.Security.Cryptography;
using System.Text;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.Extensions.Configuration;
using StackExchange.Redis;
namespace RestApi.Services;
public sealed class OtpService(
    IConnectionMultiplexer multiplexer, IOtpDelivery delivery,
    IConfiguration configuration) : IOtpService
{
    private readonly IDatabase _db = multiplexer.GetDatabase();
    private readonly byte[] _key = GetHmacKey(configuration);

    private static byte[] GetHmacKey(IConfiguration configuration)
    {
        var value = configuration["Otp:HmacKey"]
            ?? throw new InvalidOperationException("Otp:HmacKey is required.");
        var key = Encoding.UTF8.GetBytes(value);
        if (key.Length < 32)
            throw new InvalidOperationException("Otp:HmacKey must be at least 32 bytes.");
        return key;
    }

    public async Task IssueAsync(int userId, string email, CancellationToken ct)
    {
        var code = RandomNumberGenerator.GetInt32(0, 1_000_000).ToString("D6");
        var digest = Convert.ToHexString(HMACSHA256.HashData(_key,
            Encoding.UTF8.GetBytes($"{userId}:{code}")));
        if (!await _db.StringSetAsync(OtpRedisKeys.Challenge(userId), digest,
                TimeSpan.FromMinutes(5), When.NotExists))
            throw new InvalidOperationException("Challenge already active.");
        await delivery.SendAsync(email, code, ct);
    }

    public async Task<bool> VerifyAsync(int userId, string code, CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested();
        var key = (RedisKey)OtpRedisKeys.Challenge(userId);
        var stored = await _db.StringGetAsync(key);
        if (stored.IsNull) return false;
        var digest = Convert.ToHexString(HMACSHA256.HashData(_key,
            Encoding.UTF8.GetBytes($"{userId}:{code}")));
        if (!CryptographicOperations.FixedTimeEquals(
                Encoding.ASCII.GetBytes(stored.ToString()), Encoding.ASCII.GetBytes(digest)))
            return false;
        return await _db.KeyDeleteAsync(key);
    }
}

Redis exceptions propagate; verification fails closed. Provide a 32+ byte key via Otp__HmacKey. Six-digit codes need atomic attempt limits and per-account/IP throttling before production; compare and delete here is not atomic under concurrent verification. Delivery failure leaves the challenge until its 5-minute expiry.

Bu adımda sık yapılan hata: Fail-open verification or unlimited guesses. Use an atomic Lua compare/attempt/consume implementation before production.

7. Controller

Dosya yolu: RestApi/Controllers/OtpController.cs · Önerilen geliştirme

using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using RestApi.Data;
using RestApi.Models.Dto;
using RestApi.Services;
using StackExchange.Redis;
namespace RestApi.Controllers;
[ApiController]
[Route("api/otp")]
[Authorize]
public sealed class OtpController(ApplicationDbContext context, IOtpService service)
    : ControllerBase
{
    private bool TryUserId(out int id) =>
        int.TryParse(User.FindFirstValue(ClaimTypes.NameIdentifier), out id) && id > 0;

    [HttpPost("send")]
    public async Task<IActionResult> Send(CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        var user = await context.Users.AsNoTracking()
            .SingleOrDefaultAsync(x => x.Id == userId, ct);
        if (user is null) return Unauthorized();
        try { await service.IssueAsync(userId, user.Username, ct); return Accepted(); }
        catch (InvalidOperationException) { return Conflict(); }
        catch (RedisException) { return StatusCode(503); }
    }

    [HttpPost("verify")]
    public async Task<IActionResult> Verify(OtpVerifyDto request, CancellationToken ct)
    {
        if (!TryUserId(out var userId)) return Unauthorized();
        try
        {
            return await service.VerifyAsync(userId, request.Code, ct)
                ? NoContent() : BadRequest(new ProblemDetails { Title = "Invalid or expired code." });
        }
        catch (RedisException) { return StatusCode(503); }
    }
}

Send: 202, active challenge 409; verify: 204/400; unauthenticated 401, Redis outage 503. This demo is not a password-reset or login bypass flow; production should return generic send responses to prevent enumeration.

Bu adımda sık yapılan hata: DTO e-postasıyla farklı hesaba challenge göndermek; account is derived from NameIdentifier and email is read from SQLite.

F · Akış, risk ve öğrenme

HTTP → ErrorHandlerMiddleware (header redaction required) → GlobalMiddleware → Authentication/Authorization as designed → OTP Controller → Redis attempt/verify → SQLite account/password update → email provider
Success: valid, unexpired, under threshold → atomic consume → DB update → 204.
Failure: expired/wrong → increment counter atomically; Redis outage → explicit fail-closed 503, never silently accept.
  • Redis Lua only makes Redis keys atomic; sending mail, SQLite update and Redis consumption are not one transaction.
  • Wrong attempt exhaustion and resend flooding; account lockout denial-of-service tradeoff.
  • Do not put code, email, token or secrets in logs; current login logging violates intended hygiene.
  • Redis eviction/restart can invalidate outstanding OTP; communicate resend path. SQLite stores account state.

Outcomes: cryptographic random, TTL, rate limit, consume-once and failure policy. Prerequisite Mod 02 rate limiting; next Mod 09 idempotency handles retries.

Görevler

  1. Generate secure six-digit OTP.
    İpucuUse cryptographic RNG and preserve zeros.
  2. Set resend and attempt limits.
    İpucuSeparate per-user and per-IP keys with distinct TTL.
  3. Race two valid verification requests and test Redis outage.
    İpucuLua consume-once; no silent success on timeout.

Checklist / kendini değerlendir

Yanıtları göster

1) Random neden olmaz? Güvenlik için tahmin edilebilir PRNG yetersiz. 2) Neden düz OTP saklamamak? Redis read sızıntısında anında kullanım riskini azaltır; 6 haneli uzay hash ile de brute-force edilebilir. 3) GET ardından DEL problemi? Paralel istekte çift kabul. 4) Redis down? OTP kontrolünü bypass etme.

Sık yapılan hatalar

  • OTP’yi Console’a yazmak → hassas logları yasakla.
  • Tek DB/Redis arası atomiklik varsaymak → recovery/idempotent state transition kur.
  • Unlimited verification → per-user/IP attempts + resend guard.
