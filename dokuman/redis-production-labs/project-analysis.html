1. Depo ve çalışma yapısı

  • Kök çözüm: RestApi.sln; Web API projesi: RestApi/RestApi.csproj, hedef net9.0, Nullable ve ImplicitUsings açık. Referans paketler: StackExchange.Redis 3.3.1; Microsoft.Extensions.Caching.StackExchangeRedis 10.0.12; JwtBearer 9.0.2; EF Core SQLite/Design/Tools 9.0.2; BCrypt.Net-Next 4.0.3.
  • Kök docker-compose.yaml tek redis servisi tanımlıyor: image string’i redis:8.10.2, container adı redis-lab, AOF, localhost’a bind edilmiş port 6379, redis-data volume ve restart policy. Parola, maxmemory ve eviction ayarı yok. Image etiketinin registry’de mevcutluğu burada doğrulanmadı; etikete özgü özellik iddia edilmiyor.
  • .gitignore yalnızca DLL ile bin/obj girdilerini hariç tutuyor. RestApi/info.txt migration ekleme ve database update komutlarını içeriyor.
  • RestApi/Properties/launchSettings.json: HTTP 5120; HTTPS profili 7209 ve 5120 adreslerini ilan ediyor.
  • appsettings.json içindeki ConnectionStrings:DefaultConnection SQLite restapi.db dosyasını gösteriyor. Jwt:Key, EncDecKey ve Redis:ConnectionString anahtarları mevcut; gerçek değerler rapora alınmadı. Gizli değerler yapılandırma/secret store’a taşınmalı.
  • İncelenen listede test projesi, Dockerfile, Swagger/OpenAPI, BackgroundService, ILogger, health check veya Repository/Service data katmanı yok. Services/ klasöründe yalnızca PasswordManager var. Controller’lar doğrudan ApplicationDbContext kullanıyor.

Auth rotası notu

AuthController.LoginUser ham SQL’i FromSqlRaw ile çalıştırıyor ancak sorguda {0}/{1} parametre yer tutucuları kullanılmış; bunu kanıtsız biçimde SQL injection olarak nitelemiyoruz. Postman’daki LoginSql adı ve /api/auth/LoginSql yolu ise mevcut action rotası /api/auth/loginUser ile eşleşmiyor. Bu action parola alanını veritabanındaki Password ile doğrudan karşılaştırıyor; Register BCrypt hash sakladığı için bu iki login yolunun davranışı da tutarlı değil.

4. Redis ve pipeline

  • Program.cs Redis:ConnectionString yoksa startup’ta exception fırlatıyor. IConnectionMultiplexer singleton; AbortOnConnectFail=false, ConnectRetry=3, ConnectTimeout=5000ms, SyncTimeout=5000ms; ConnectionMultiplexer.Connect senkron çağrılıyor.
  • Microsoft.Extensions.Caching.StackExchangeRedis 10.0.12 paketi csproj’de var ancak Program.cs’de AddStackExchangeRedisCache çağrısı yok. Dolayısıyla IDistributedCache kaydı bu kod tarafından yapılmıyor; ilgili yorum yanıltıcı.
  • Gerçek pipeline sırası: Development dışındaysa HSTS + HTTPS redirection; CORS; Development exception page (Development’ta); ErrorHandlerMiddleware; GlobalMiddleware; ikinci HTTPS redirection; Authentication; Authorization; MapControllers. Rate limiter middleware satırı yorumda. ASP.NET Core 9 pipeline’da UseRateLimiter authentication’dan sonra konumlandırılmalı ki authenticated identity partition key’i okunabilsin.
  • ErrorHandlerMiddleware.Invoke Console.WriteLine ile username, IP, path, method ve bütün request header’larını yazıyor; Authorization header’ı da bu döngüye girer. Exception’ı status’a çevirir; Redis bağlantı/timeout exception’ları için özel eşleme yok, varsayılan 500 ve exception.Message response’a yazılır.
  • Program.cs AddRateLimiter içinde fixed window 1 istek/sn, queue 0; partition User.Identity.Name yoksa Host header. Kayıt edilen built-in limiter uygulama süreci belleğinde çalışır; şu an middleware pasif ve OnRejected/Retry-After tanımı yok.

5. JWT, roller ve Postman farkları

  • Program.cs signing key doğrular; issuer/audience doğrulaması false; SaveToken true; RequireHttpsMetadata false. ValidateLifetime açıkça belirtilmemiş olsa da token validation parametrelerinin varsayılanı geçerli. JWT anahtar değerleri bu rapora alınmadı.
  • AuthController Login token claim’leri: NameIdentifier, Name ve Role. JTI, iss, aud yok. Mevcut rol isimleri controller guard’ları olan Product ve Note. Policy, Admin, User rolü bulunmuyor.
  • Postman NoSQL.json isteği User Login Sql için /api/auth/LoginSql çağırır; gerçek action loginUser olduğundan rota uyuşmaz. Product List istek tanımında auth gösterilmiyor, fakat controller sınıfı `[Authorize(Roles="Product")]` içeriyor ve `[AllowAnonymous]` yok.
  • Login DTO’da City zorunlu. Register ise DTO değil User modeli aldığı için Username e-posta/City doğrulamaları ona otomatik uygulanmıyor; Register cevapta parola hash’ini içeriyor.

6. Bilinen zayıflıklar ve eğitim bağlantıları

  • Controller düzeyinde rol sınırları ve kullanıcı sahipliği kontrolü eksik/uyumsuz örnekleri vardır; Note endpoint’leri bütün notları döndürüyor ve Create gövdeden UserId alıyor. Modüller 01, 04, 05 ve 09 sahiplik/idempotency kararlarını öneri olarak ele alır.
  • Login parola türevleri ve middleware tüm header’ları logluyor; Authorization/Bearer sızıntı riski var. Register hash’i cevaplıyor; Postman rota ve auth beklentisi de kodla farklı. Modüller 03 ve 06 gizli verinin log/yanıtta korunmasını vurgular.
  • Rate limiter tanımlı fakat etkin değil; etkinleştirilse bile süreç içi limiter’dır. Modül 02 dağıtık limit alternatifini gösterir.
  • Mevcut products:all cache’inde Update/Delete invalidation eksik; Create invalidation DB yazımından önce. Redis çağrıları fallback’siz; TTL sabit ve cache stampede koruması yok. Modüller 11–12 gerçek akışı inceler.
  • SQLite ve Redis arasında atomik transaction yoktur; çok instance yazma, stok veya ödeme doğruluğu için tek başlarına cache/lock çözümü yeterli değildir.

Bunlar eğitim materyalinin incelediği mevcut kod davranışlarıdır; bu çalışmada RestApi kaynakları üzerinde değişiklik yapılmadı.
